# Sprint note — 2026-09-15 ("Proactive briefing engine, issue #65 status")

This is a status/documentation pass, not a new build: the briefing engine
itself (`scripts/briefing.py` + `n8n/workflows/proactive-briefings.json`)
already shipped in commit `a575c5a` (PR #127, 2026-09-14). What was missing
was a written record of what's live, what's degraded, and how a human
activates it — this note plus a small config gap fix close that out.

## What's already live (commit a575c5a, PR #127)

- **`scripts/briefing.py`** — stdlib-only driver with two modes:
  - `brief` — composes the 07:00 morning brief: fetches Open-Meteo weather,
    asks ai-core's `/chat` (with `List_Calendar_Events`/`List_Reminders`
    tool access + memory search) to write the brief text, sends it via the
    Telegram Bot API to `TELEGRAM_OWNER_ID`.
  - `nudge` — every-15-min check: asks ai-core for today's remaining
    calendar events as bare JSON, sends an "in ~N min" Telegram message for
    any event starting within the next 30 minutes, and records a
    `title@start` key in `scripts/.briefing_state.json` so each event nudges
    **exactly once**. Quiet hours 23:00-07:00 (Asia/Bangkok) are enforced by
    skipping the run entirely — no urgent-override path exists yet (nothing
    in this stack currently flags an event "urgent").
  - Calendar/Reminders context is fetched **only** through ai-core's own
    mcpo tool loop, matching #125's design — the script never shells
    `osascript` directly (that hangs on the macOS TCC permission prompt in
    headless sessions).
- **`n8n/workflows/proactive-briefings.json`** — version-control snapshot of
  the two schedules (`Daily 07:00`, `Every 15 Minutes`) calling
  `scripts/briefing.py` via `executeCommand`, following the same shape as
  `n8n/workflows/offload-watcher.json`. Marked `"active": false` with a note
  explaining why (see below).
- **`ai-core/nevnew_ai_core/tools/mcpo.py`** fix — mcpo tool calls now pass
  `base_url` to the `AsyncClient`; previously every mcpo tool execution
  (including `List_Calendar_Events`/`List_Reminders`) silently failed
  because relative tool paths never resolved. This was blocking ALL mcpo
  tools, not just the briefing engine's.

## Gap fixed in this pass

- **Weather location was hardcoded to Bangkok** in two places (`fetch_weather`
  ignored its own `LAT, LON` constants and inlined the coordinates in the
  Open-Meteo URL), so the `.env`-overridable location the issue asked for
  didn't actually exist. Fixed: `scripts/briefing.py` now reads
  `NEVNEW_HOME_LAT` / `NEVNEW_HOME_LON` from `.env` (documented in
  `.env.example`), falling back to the Bangkok default if unset.
- Removed a stray emoji from the nudge message template (repo convention is
  no emoji in product-facing copy).

## Why the n8n workflow is inactive (known, by design)

The workflow file carries this note verbatim:

> SUPERSEDED 2026-09-14: triggers moved to system cron
> (`nevnew_briefing_brief`/`nevnew_briefing_nudge`) because n8n
> ExecuteCommand-spawned Python hangs at interpreter startup in the
> task-runner sandbox (see Sprint 8 log). Kept for reference; DO NOT
> activate or briefings double-fire.

That system-cron install was never actually landed anywhere in this repo
(no crontab entries, no install script) — this note fixes that gap by
spelling out the exact manual step below rather than leaving it implicit.

## Still degraded — needs a human, not code

- **Calendar/Reminders are unverified live** — `n8n/macos_tools.applescript`
  (`list_events`/`list_reminders`) will return
  `"ERROR (Reminders/Calendar — check automation permission): ..."` under a
  headless n8n/mcpo process until a human grants Calendar + Reminders
  automation access to the n8n/mcpo process in **System Settings > Privacy
  & Security > Automation** (this is the TCC gap tracked by #125). The brief
  degrades gracefully when this happens: ai-core's tool-loop sees the ERROR
  string and the composed brief will say something like "calendar
  unverified" instead of failing the whole message — same behavior #125
  already established for reactive chat. **No code change needed once the
  grant is made** — just re-run `scripts/briefing.py brief --dry-run` to
  confirm real events come back instead of an ERROR string.
- **Email is not connected** (Google bundle, #4/#44) — the brief prompt
  explicitly tells the model to say so in one line rather than fail or omit
  it silently.

## Manual activation steps (for the PO — not run by this pass)

1. **Grant TCC permissions** (#125, human-only, System Settings GUI) before
   expecting real calendar/reminder data — see above.
2. **Install the cron triggers** (the workflow JSON is intentionally left
   `"active": false`; do not activate it in n8n — see the sandbox-hang note
   above). Recommended, matching this repo's existing cron-dedup pattern
   (`CLAUDE.md` global rule: strip old entries by marker before re-adding):
   ```bash
   (crontab -l 2>/dev/null | grep -v nevnew_briefing_brief; \
    echo "0 7 * * * cd '/Volumes/Ugreen_WD 1.0 TB/grit/nevnew' && /usr/bin/python3 scripts/briefing.py brief >> /tmp/nevnew_briefing.log 2>&1 # nevnew_briefing_brief") | crontab -
   (crontab -l 2>/dev/null | grep -v nevnew_briefing_nudge; \
    echo "*/15 * * * * cd '/Volumes/Ugreen_WD 1.0 TB/grit/nevnew' && /usr/bin/python3 scripts/briefing.py nudge >> /tmp/nevnew_briefing.log 2>&1 # nevnew_briefing_nudge") | crontab -
   ```
3. **Set real weather coordinates** if the owner's home isn't Bangkok: add
   `NEVNEW_HOME_LAT` / `NEVNEW_HOME_LON` to `.env` (see `.env.example`).
4. **Verify end to end**: `python3 scripts/briefing.py brief --dry-run` and
   `python3 scripts/briefing.py nudge --dry-run` from the repo root (needs
   `TELEGRAM_BOT_TOKEN`/`TELEGRAM_OWNER_ID`/`AICORE_API_KEY` in `.env` and
   ai-core reachable at `http://localhost:8010`) — confirm the composed
   brief text looks right and, once TCC is granted, that it contains real
   events instead of "calendar unverified".
