## Per-goal detail

### P0-1 · LiteLLM↔Postgres (Prisma) DB reconnect (tracks #92–#116)
- **Symptom:** repeated `utils.py:5512 - Prisma DB reconnect failed` and
  `reset_budget_job.py: Failed to reset budget` (roughly every 30s–1h).
- **Investigate:** is the `postgres` container up/healthy? Is the DSN in
  `config.yaml` correct + reachable from the litellm container? Prisma client
  version vs litellm build? `max_connections` / pool exhaustion? disk pressure?
- **Fix:** stabilize the connection (correct DSN, pool settings, a `postgres`
  healthcheck, litellm restart policy). Add a litellm healthcheck so a dead DB is
  caught, not just logged.
- **Verify:** 30-min clean `docker compose logs litellm` (no new reconnect lines);
  **no new auto-bugs** filed for 24h.

### P0-2 · mcpo crash-loop (#81)
- **Symptom:** mcpo restart-loops; logs show it dialing a deleted n8n MCP endpoint (404).
- **Fix:** point mcpo at a live MCP endpoint (or disable the dead reference); add a
  healthcheck so a 404 endpoint doesn't loop-restart.
- **Verify:** `docker ps` shows mcpo `Up` (no `Restarting`) for 30 min.

### P0-3 · telegram-bot + cloudflared crash-loop (#74)
- **Symptom:** both crash-loop when a stale shell `TELEGRAM_BOT_TOKEN` overrides `.env`
  during `docker compose` interpolation; bot was down ~2h.
- **Fix:** make env loading robust — rely on compose `env_file` (not shell), validate
  `TELEGRAM_BOT_TOKEN` / `NINEARM_API_KEY` at startup and fail fast with a clear
  message (not a crash-loop). Document the `env -u TELEGRAM_BOT_TOKEN` recreate workaround.
- **Verify:** recreate with `env -u TELEGRAM_BOT_TOKEN docker compose up -d --force-recreate`;
  bot stays up; `getMe` returns 200.

### P1 · ai-core `/ready` false negative (#66)
- **Symptom:** `/ready` pings `/v1/health/liveliness` (404) → reports not-ready when healthy.
- **Fix:** point `/ready` at a real health endpoint (or add one that reflects true readiness).
- **Verify:** `GET /ready` returns 200 when the service + its deps are healthy.

### Housekeeping · close #112, #113
- The cline single-word-prompt parser bug is **fixed** (leading-space prefix on the
  prompt in `telegram-bot/bot.py:_run_cline`, deployed 2026-09-13). Close both with a
  note referencing the fix. (Pending the user's live Telegram round-trip confirmation.)
