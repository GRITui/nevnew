## Done

- **Telegram bot (issue #11) wired up** — `telegram-bot/` (bot.py + Dockerfile), new `telegram-bot` service in `docker-compose.yml`. Owner-only whitelist, in-memory per-user history (last 20 messages, resets on restart), forwards to LiteLLM (`model=NevNew`, persona applied via the existing callback, no duplication), graceful "having technical trouble" reply on any LiteLLM/network failure. Verified live 2026-09-05: bot started, round-tripped a real message through LiteLLM, replied. Follow-up if needed: history doesn't survive a restart — fine for MVP per issue #11's scope.
- **Telegram bot: `cline` fallback on OpenRouter 429s** — when LiteLLM 429s (see OpenRouter daily-cap gap above), the bot now shells out to the `cline` CLI (`telegram-bot/bot.py: _run_cline`/`_gate_cline_reply`) using the already-authenticated Cline account mounted in from the host (`~/.cline` → `/cline-home`, a separate quota pool from the OpenRouter key). Locked down since `cline` is a full coding agent, not a chat API: `--auto-approve false`, empty scratch cwd, persona reused from `callbacks/nevnew_persona_prompt.py` (factored out so telegram-bot can import it without pulling in LiteLLM), and every reply passes through a chat-gate (rejects empty output, anything where cline attempted a tool call, strips stray markdown-image syntax, caps to Telegram's message length) before it can reach the user. Requires Node 20 + the `cline` npm package in the container image (`telegram-bot/Dockerfile`). Known cline CLI quirk worked around: a bare single-word prompt (e.g. `"hi"`) makes cline's own arg parser bail with "Unknown command or unquoted prompt" — fixed with a leading-space prefix on the prompt passed to cline.
- **`scripts/error_watcher.py` — auto-detect real errors → file GitHub bug issues** — tails all 4 containers' docker logs (state file tracks last-checked timestamp per container so cron runs only see new lines), dedupes by a normalized signature so the same error only files once, and skips a `KNOWN_NOISE` allowlist of expected/operational messages (currently: OpenRouter's daily-cap message, and the bot's own log line for it) so routine rate-limiting doesn't spam the tracker. Files via `gh issue create --label bug`. Detection only — no auto-fix — by design (see issue discussion 2026-09-05). Installed in crontab, every 20 min (marker `nevnew_error_watcher`). Verified live 2026-09-05: correctly caught a real bug (cline's single-word-prompt parser quirk, above) as issue #14, and initially over-fired once on a litellm traceback that was actually the known daily-cap noise (issue #13, closed) — fixed by widening the noise-matching window from 3 to 30 log lines, since litellm's exception-chaining preamble can put 10+ lines between the informative ERROR line and a later bare `Traceback (most recent call last):` header for the same incident.
